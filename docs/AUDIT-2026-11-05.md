# Repository audit and improvement plan — 5 November 2026

**Repository:** `LIN4CRE/Recompa` · **Branch:** `arena/de43ce7f-recompa`
**Baseline commit:** `993385c` (v0.1.0, already live at <https://recompa.vercel.app>)

This is a follow-up audit of an already-complete application, not a rebuild. The
previous completion report (`docs/COMPLETION-REPORT.md`) describes the original
build; this document records what a fresh, independent pass found, what was
changed, and what was actually verified.

The app is a static, client-side React 19 / TypeScript / Vite 8 application with
two compiled-in emulator cores (jsnes, mGBA-WASM), an optional GPL PlayStation
core fetched at build time, IndexedDB storage, and an opt-in loopback Node
processing service. There is no server-side runtime, no account and no database
to migrate. Most of the Phase 2 audit therefore concerns browser correctness,
honest feature reporting, deployment headers and CI supply chain.

## B. Findings, prioritised

### P0 — Critical

| # | Problem | Location | Why it matters | Fix | Verification |
| --- | --- | --- | --- | --- | --- |
| 1 | **PlayStation playback could never start.** The adapter created an `iframe`, set `src="about:blank"`, read `frame.contentDocument` and wrote the bootstrap document **before** inserting the frame into the DOM. Modern Chromium returns `null` for `contentDocument`/`contentWindow` on a detached iframe, so `create()` threw `Could not create the emulator frame` on every launch. | `src/engines/psx/adapter.ts` `create()` | A flagship advertised feature was dead, with no test covering it (the E2E suite had never been executable in the authoring sandbox). | Extract `mountBootstrapFrame()` into `src/engines/psx/frame.ts`; insert the frame first, then write. Revoke blob URLs and restore the canvas on failure. | Real-browser probe of all iframe variants; new unit test with a fake DOM that enforces attach-before-read; new Playwright test that mounts a bootstrap frame in Chromium and asserts the inline script ran and `postMessage` reached the parent. |
| 2 | **The planner could choose an engine that does not exist.** `install-check.ts` probed EmulatorJS `loader.js` and reported `emulatorjs-nes` as installed. Every NES ROM therefore selected `Emulation (WebAssembly core) · EmulatorJS + FCEUmm` over the working `jsnes`, but there is no FCEUmm payload, no NES adapter and no such entry in `ENGINE_ADAPTERS`; PLAY failed with *"Engine … is not installed in this build"*. | `src/engines/install-check.ts`, `src/core/planner.ts`, `src/engines/descriptors.ts` | The primary use case (NES ROM → playable emulation) was broken and the UI confidently named a component that is not shipped. | Discovery now HEADs the real `pcsx_rearmed-wasm.data` payload (or reads the install manifest's `cores` array), always reports `jsnes`/`mgba-wasm`, and never reports `emulatorjs-nes`. The planner rejects `emulatorjs-nes` with an honest blocker and filters **all** accepted candidates by registered adapter IDs. Descriptor/compatibility text corrected. | New `install-check` unit tests (no `loader.js` probe, offline → built-ins, manifest-only → PSX); planner regression asserting a bogus installed `emulatorjs-nes` cannot beat `jsnes`; full Playwright flow now boots jsnes. |
| 3 | **The player could stay on "Loading core…" with status `stopped`.** `useEmulator()` returns a fresh object on every render; three `Player.tsx` effects depended on that whole object, so the teardown effect (which calls `stop()`) ran on every render and aborted the session immediately after `start()` created it. React 19 StrictMode's simulated mount → cleanup → mount made it deterministic, and the boot effect's `startedRef` guard then blocked the second boot. | `src/ui/player/Player.tsx` | A real user could not launch any ROM in a development/StrictMode build; the bug would also surface on any remount in production. | Effects depend only on the hook's memoised `start`, `stop` and `actions` (plus a status ref for the input handlers); the boot effect resets `startedRef` in cleanup so a StrictMode remount can boot again. | New jsdom unit test asserting the teardown effect does **not** re-run on re-render; full Playwright smoke test now reaches a running jsnes session at measured fps, saves/restores state, captures a screenshot and verifies. |

### P3 — Low / decisions left to the owner

- `index.html` carries `<meta name="robots" content="noindex">`. This is
  deliberate-looking for a privacy-focused tool but prevents a public app from
  being indexed. **Left unchanged** — it is a product decision, not a defect.
- Browser-side static recompilation remains unimplemented because no WASM build
  of N64ModernRuntime/RT64 is published. The planner already reports this as
  `blocked` with prerequisites. Not changed.
- Vercel project settings use Node 26.x while `.nvmrc`, CI and local builds use
  Node 22.22.3. Vite 8 officially requires Node 20.19+/22.12+; the existing
  production build succeeded on 26.x, so this is a documented inconsistency
  rather than a proven defect. Aligning it is an owner decision in the Vercel UI.
- A newer `vite` patch (8.3.6 vs the locked 8.3.5) and `jsdom` 31 exist, but
  there is no advisory and the user asked to avoid unnecessary dependency churn.
  Left pinned.
- `docs/COMPLETION-REPORT.md` §H describes E2E as permanently blocked and CI as
  billing-locked. Both were true at that time; the report is now marked as a
  point-in-time document rather than rewritten.
- The fingerprint catalogue's provenance link is an upstream mirror, not a
  signed source. Not changed (the data is metadata only and cannot affect
  execution safety).

## C. Deliberately not changed

- No framework, dependency or architecture changes; `npm audit` reports 0
  vulnerabilities and the pinned cores are covered by regression tests.
- The 31,655-entry fingerprint catalogue is committed data with CC-BY-SA-4.0
  attribution and a CI freshness check; it was not regenerated.
- `public/_headers` / `vercel.json` CSP directives (`unsafe-eval`,
  `wasm-unsafe-eval`) are documented trade-offs required by EmulatorJS's
  decompressors; removing them would break multi-track PlayStation discs.
- GPL cores are still fetched at build time and never committed.
- The optional processing service still supports `RECOMPA_ALLOW_REMOTE=1` for
  self-hosted operators; the *client* now refuses to send data to a remote
  endpoint, which is the honest boundary for the deployed app.

## G. Research: official docs, versions, advisories, licensing

Decisions above were checked against current sources on 5 November 2026. No
dependency was upgraded on the strength of "newest is best"; the checks were
used to confirm compatibility and to justify leaving things pinned.

- **React 19 StrictMode** (react.dev/reference/react/StrictMode): development
  builds deliberately run effects as setup → cleanup → setup to expose missing
  cleanup. The documented remedy is to make effects idempotent and clean up
  fully — not to disable StrictMode and not to use a ref to skip the second
  invocation. This directly motivated the P0 #3 fix (reset the guard in
  cleanup; keep StrictMode).
- **Vite 8** (vite.dev/blog/announcing-vite8, vite.dev/guide/): requires
  Node.js 20.19+ or 22.12+ and ships Rolldown. Local Node 22.22.3 satisfies the
  requirement; Vercel's Node 26.x is newer and already produced a successful
  production build, so no runtime migration was made.
- **CSP `wasm-unsafe-eval` / `unsafe-eval`** (MDN, CSP `script-src`):
  `wasm-unsafe-eval` permits WebAssembly compilation without permitting general
  JavaScript `eval()`; `unsafe-eval` is broader and does defeat much of a CSP's
  purpose. The deployed policy keeps both because EmulatorJS's
  `extractzip.js` calls `eval()`. The residual risk is now documented in
  `SECURITY.md` and `docs/SECURITY.md` instead of being glossed over.
- **Versions** (`npm view <pkg> version`, registry.npmjs.org): react/react-dom
  19.3.1, vite 8.3.6, vitest 5.1.0, typescript 7.0.2, @playwright/test 1.64.1,
  jsnes 2.1.0, @thenick775/mgba-wasm 2.6.0, zustand 5.0.16, fflate 0.8.3,
  idb 8.0.4, jsdom 31.0.0. The lockfile's vite 8.3.5 and jsdom 30.1.3 are one
  patch/one major behind with no advisory, so they were left alone.
- **Advisories**: `npm audit` and `npm audit --omit=dev` report 0
  vulnerabilities (see section E). No paid security service was introduced.
- **Licensing**: EmulatorJS 4.2.3 and `pcsx_rearmed` are GPL-3.0 payloads
  fetched at build time, verified against the npm registry `dist.shasum`, never
  committed, and shipped with committed GPL licence texts. No-Intro DAT metadata
  is CC-BY-SA-4.0 with attribution in the UI. `THIRD-PARTY-NOTICES.md` and
  `scripts/collect-licenses.mjs` were corrected so attribution names only
  components actually shipped.
- **GitHub Actions**: every `uses:` SHA in `SECURITY.md` was resolved from the
  upstream repository via `gh api repos/<owner>/<repo>/commits/<tag>` on
  5 November 2026. Account-level settings that cannot be committed (Dependabot
  alerts, secret scanning, push protection, branch protection/rulesets, default
  token permissions) are enumerated with exact UI paths in `SECURITY.md`.
